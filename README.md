# arm_payload_gravity — 末端负载辨识 · 重力前馈补偿 · 到位验证

**目的**：手臂末端加了工作结构后变重，作者现有控制（纯 PD + 按 URDF 算的重力前馈）会稳态下垂、到不了位。
本项目：①用若干固定姿态自动**测出末端负载的等效质量与质心**；②把负载项**加进重力前馈**；③用同一组姿态
对比"现状 / 补偿 / 补偿+修正"三种方案的**到位精度与耗时**，证明精度提升且不变慢。

端口 **10183**。默认仿真模式，无机器人可跑通全流程；真机只在显式加 `--allow-real-motion` 且网页点「接管」后才发令。

## 原理一页纸

手臂静止时电机输出力矩 = 重力矩（+ 一点摩擦）。对末端点质量 m、质心 c（末端连杆系）：

```
τ_true(q) = α · τ_arm_URDF(q) + Y(q) · θ,     θ = [m, m·cx, m·cy, m·cz]
```

`Y(q)`（7×4）由 FK 解析给出（`gravity.py`），**对 θ 线性** → 多姿态静止采样后一个最小二乘同时解出质量与质心
（可选再解 α：URDF 臂自重相对实物的比例）。`τ_true` 用底层 PD 律重构 `kp·(q_cmd−q) − kd·dq + τ_ff`
（这正是造成下垂的那份力矩），也记录 `tau_est` 供对比。摩擦用"双向逼近"抵消：每个姿态分别从 +δ、−δ 停下各采一次。

补偿：把 `α·τ_arm + Y·θ` 作为新前馈。真机侧是**子类化**作者 `H2ArmController`、只替换 `_grav_model`
（`controllers.py: PayloadArmController`），发令通道 / 限速 / 钳位 / 权重渐入渐出 / 力矩上限全部沿用，一行未改。

```bash
conda activate abyss
```

## 操作流程（按顺序做）

### A. 先在仿真里走一遍（10 分钟，不碰机器人）

```bash
python server.py            # 打开 http://<ip>:10183/，左上角徽标应显示「仿真」
```

1. 左侧「仿真真值」把负载改成你估计的新末端（比如 1.5 kg，质心 x 0.12），点「写入真值」。
2. 顶部「接管」。
3. 面板 1：「新建」姿态集（名字随意，如 `test`）→ 面板 1b「开始示教」→ 拖滑块把手臂摆到一个位置 → 按**空格**（记录）→
   再按空格（恢复卸力）→ 换个位置…… 记 8 个以上，看条件数降到 10 以下 → 「结束示教」。
   偷懒可以直接「生成为新姿态集」。
4. 面板 2「开始测量」，等它跑完（约 8 姿态 × 2 方向 × ~10 s）。
5. 面板 3「求解」（勾 α）→ 对照真值看误差是否 <0.05 kg / <5 mm → 「应用并保存」。
6. 面板 4「开始验证」，看三方案的误差表：基线几度、补偿后零点几度、轨迹时长一致。
7. 面板 5 随便填个目标「出发」，确认到位报告正常。

目的是熟悉每个按钮在真机上会干什么；仿真里没有任何风险。

### B. 真机首次（需要两个人：一个操作网页，一个扶手臂/守急停）

前置检查：网页顶部会显示 **rt/arm_sdk 占用检测**（服务端只读订阅 `rt/arm_sdk`，接管前收到任何 LowCmd_ = 别人在控臂）。
显示「空闲，可以接管」才能点接管；显示红色「有其他发布者（xx Hz，权重 w，kp）」时接管按钮禁用、服务端也会拒绝，
下面会列出本机疑似进程（`reach_server`、`calibration_replay`、`hand_eye_3D --arm-control`、teleop 的 `python -u - AUTO 60 192.168.123.162 …` holder 等）。
两个程序同时发 `rt/arm_sdk` 的典型症状：我们「接管」显示成功，但「卸力」后手臂纹丝不动 / 发抖——是对方的 kp 在顶着。
发布者也可能在另一台机器上（本机列表为空但检测仍报占用），需要在对方机器上停。
机器人站稳或挂架上；手臂周围没有障碍；新末端已装好。

```bash
python server.py --mode real --iface enp86s0                       # 第一步先只读
```

1. **只读观察**：徽标「真机（只读）」，右侧状态栏 `rt/lowstate OK`。关节表里实测角随你手推手臂变化 → DDS 通了。
2. 重启为可运动：`python server.py --mode real --iface enp86s0 --allow-real-motion --max-speed 0.15`。
3. 面板 1「新建」姿态集，名字写清末端（如 `夹爪A_1.5kg`）。
4. 扶手臂的人**先托住前臂**，操作员点「接管」（弹确认；权重 1 s 渐入，手臂应无跳动，只是变"硬"）。
   面板 1b 里的「静止判定」阈值（速度阈 / 漂移阈 / 窗口 / 超时，默认 0.03 rad/s、0.004 rad、0.4 s、3 s）按需要放宽：
   锁定后超时也**照常按均值记录**，只是标注实测的 max|dq| 和漂移，据此调阈值。
5. 「开始示教」（弹确认）：手臂卸力。**此时负载没补偿，它会往下坠**，扶手臂的人要撑着。推到位 → 操作员按空格 →
   手臂自己锁住（可以松手）→ 网页显示"已记录 pXX" → 再按空格恢复卸力 → 下一个。
   要点：8～12 个姿态；有高有低、有前伸有外展，腕部至少翻转 ±60°、俯仰两个方向；避开躯干和头。看条件数 <10。
   「结束示教」：手臂刚性保持。
6. **逐个点姿态名**让手臂自己走到每个姿态（限速 0.15 rad/s，很慢），确认走过去的路径不会撞。会撞的右键删掉。
7. 面板 2「开始测量」，操作员手放在「急停(保持)」上。全程约 姿态数 × 2 × 15 s。
8. 面板 3 选刚生成的会话「求解」：先看**不勾 α** 的结果，再看勾 α 的；两者 m 应接近、质心不确定度 <1 cm、α 在 0.9～1.15。
   若勾 α 后 m 变负或 α 离谱 → 姿态不够多样，回第 5 步补几个。再用「力矩源 tau_est」解一次对照，差得多说明 kp 实际值/电机常数有偏。
9. 「应用并保存」→ 关节表里 τ_ff 立刻变化，手臂位置基本不动（说明补偿与实际相符；若明显抬起/下沉说明解错了，点「清除」）。
10. 面板 4「开始验证」（可先勾 2 个姿态试）。验收标准：**补偿方案的最大关节误差 ≤ 基线的 1/3，轨迹时长一致**。
11. 面板 5：填你要的关节目标「出发」——这就是最终用法。修正次数填 0 是纯前馈；填 1～2 可再压到摩擦死区以内，代价 +0.5 s/次。
12. 结束：手臂走回 home（面板 5「填 home」→「出发」），扶住手臂，「释放」。

### C. 以后换末端 / 日常

换一个末端结构 = 新建一个姿态集（或复用旧的）→ 测量 → 求解 → 应用并保存。`config/payload_<arm>.json` 只存最后应用的一组；
每次测量会话的解都在 `data/measure/<会话>/payload_*.json` 里，「应用已保存的」可随时切回。
服务重启后前馈回到作者现状（不自动加载），需要点一次「应用已保存的」。

## 面板说明

1. **接管**（仿真直接点；真机会弹确认，权重 1 s 渐入，从当前实测姿态开始保持）。
2. **姿态集**（`config/posesets/<名字>.json`，可建多个、可命名，例如按不同末端负载各建一个）：
   - **示教（推荐）**：「新建」一个姿态集 → 「开始示教」（手臂卸力，⚠ 真机要先扶住）→ 手推到想要的位置 →
     按 **空格**：手臂锁定当前姿态、等静止、均值读取实测关节角、追加进姿态集 → 再按空格恢复卸力推下一个 → 「结束示教」。
     建议 ≥8 个，腕部多翻转/俯仰，手臂有抬高/外展变化；面板实时显示回归矩阵**条件数**（<10 好，>50 说明姿态太雷同）。
     注：锁定后手臂会从手扶位置略下垂再静止，记录的是它**实际能停住的姿态**，这正是后面测量要用的。
   - 「记录当前姿态」：不卸力，直接把当前实测角追加（例如用单点到位面板摆好后）。
   - **自动生成**：安全盒子内随机 + 贪心 D-最优选点（条件数≈1.5），存成新姿态集；没有自碰撞检查，
     上真机前**逐个点姿态名**让手臂单独走一遍看 3D 视图。
   - 右键姿态名 = 删除该姿态；「删除」= 删除整个姿态集。测量/验证都用当前选中的姿态集。
3. **开始测量**：自动走完姿态集，每个姿态双向逼近各静止一次、取均值帧存样本，会话在 `data/measure/<时间>_<arm>/`。
4. **求解**：选会话、力矩源（推荐 PD 重构）、是否拟合 α → 显示 m ± σ、质心 ± σ、残差 RMS 前后、折算下垂角。
   仿真模式还会对照真值给出误差。**应用并保存** → 写入控制器前馈并存 `config/payload_<arm>.json`。
5. **到位验证**：三方案各走一遍姿态集，表格给每姿态的最大关节误差、末端位置误差（FK）、轨迹时长、静止时长、合计。
   三方案共用同一轨迹与限速，所以轨迹时长一致；差别在稳态误差。结果存 `data/validate/`。
6. **单点到位**：手填 7 个关节角（或"填当前实测"/"填 home"），出发后报告误差与耗时；可选 k 次修正。

急停：「急停(保持)」停止任务并让手臂冻结在当前指令角（仍接管）；「释放」渐出交还本体（真机要有人扶）。
真机释放后服务端会重建控制器实例（作者的 `H2ArmController` 是一次性的，线程不能重启），负载前馈沿用，可以再次接管。

## 仿真模式说明

`SimArmController` 用与作者一模一样的控制律（50 Hz、权重渐入、矢量同步限速、URDF 钳位、重力前馈），下面挂一个
简化关节动力学：**真实负载 + 臂质量比例误差 + 库仑/静摩擦 + 粘滞**。因此能复现"纯 PD 下垂几度"与"摩擦死区"。
仿真真值（负载 kg / 质心 / 臂质量比例 / 摩擦比例）在网页左上面板可改，控制器看不见它们。

仿真闭环结果（真值 1.2 kg @ [0.10, 0, −0.02]，臂质量 ×1.04，8 姿态双向）：辨识 m=1.189 kg、质心误差 <1 mm、α=1.045；
到位误差 基线 4.4° / 48 mm → 补偿 0.27° / 2.6 mm（耗时相同）→ 补偿+2 次修正 0.15° / 1.1 mm（+1.8 s）。

## 文件

| 文件 | 作用 |
|---|---|
| `gravity.py` | 臂重力模型（与作者对拍一致）+ 负载回归矩阵 `Y(q)` + `GravityWithPayload`（前馈替身） |
| `controllers.py` | `SimArmController`（仿真物理）/ `PayloadArmController`（真机，子类化作者）/ `ReadOnlyH2Arm` |
| `motion.py` | 五次多项式走点、静止判据、均值采样 |
| `poses.py` | 姿态集读写（多个、可命名）、示教追加、自动生成（安全盒子 + D-最优） |
| `identify.py` | 测量序列 `MeasureRunner`、最小二乘 `solve_payload`、会话读写 |
| `validate.py` | `ValidateRunner` 三方案对比、`GotoRunner` 单点到位、修正迭代 |
| `server.py` / `frontend/` | HTTP API + 网页（3D 骨架、质心标记、面板） |
| `config/posesets/*.json` | 姿态集（示教/生成）；`config/payload_<arm>.json` 应用过的负载参数 |

## 局限 / 注意

- **真机部分未在硬件上运行过**。首次上机：`--max-speed 0.15`、先只读模式看关节表正常、再接管、逐个走姿态、再测量。
- 同一时刻只能有一个程序发布 `rt/arm_sdk`；接管前服务端听 1 s 有消息就拒绝。接管后用「总频率 − 我们的 50 Hz」判断是否
  又有人插进来（顶部变红，提示立即释放）。仿真面板勾「模拟他人占用」可以演练这条逻辑。
- 负载模型是**点质量**（m + 质心），对静态重力足够；不辨识惯量/摩擦。摩擦死区留下的剩余误差靠"修正"迭代消掉。
- 自动生成的姿态集只做了工作空间盒子约束，**没有自碰撞检查**；生成后务必在仿真里先看一遍。示教的姿态集是你手推出来的，没这个问题。
- 示教卸力时真机 kp=0，只剩重力前馈（`grav_in_float=True`，按实测角算）：负载还没补偿前手臂会往下坠，**必须先扶住再点开始示教**；
  已经应用过负载参数后再示教会轻很多（近似失重）。
- 躯干视为直立（重力 (0,0,−1)）；作者控制器有 `use_imu_gravity` 选项，本项目未开。
- 腕三关节力矩小（额定 10 Nm），噪声占比高，求解里按关节残差自动加权；`tau_est` 源仅供对照。
